# 吉林大学本科生绩点计算器 UI 重构设计

> 日期：2026-08-20  
> 状态：用户已确认，等待书面复核  
> 范围：重构应用工作台 UI，不修改计算核心、导入规则、重复课程判定或 IndexedDB 数据结构

## 1. 目标

把现有纵向卡片式页面重构为现代桌面生产力软件风格的单窗口工作台：左侧承载功能导航和结果摘要，右侧至少三分之二空间始终用于逐行展示课程。

本次重构必须达到以下结果：

- 每门课程固定占一行，直接显示课程名、成绩、学分、绩点和是否为保研课程；
- 功能入口集中在左侧，不再通过多个纵向页面区块组织功能；
- 课程清单在导入、规则、导出和编辑操作期间保持可见；
- 删除渐变、玻璃、发光、大圆角、大面积彩色卡片和营销式文案；
- 使用中性、克制、符合桌面生产力软件习惯的视觉语言；
- 保持现有业务结果、导入能力、自动保存和导出功能不变。

## 2. 明确不变的范围

以下能力不因 UI 重构而改变：

- 保研 GPA、加权平均分和算术平均分的计算方式；
- 同课程号只保留最高有效成绩、同名不同课程号不合并的规则；
- 百分制、五级制折算及用户自定义绩点表；
- `.xls`、`.xlsx` 和 `.csv` 导入、预览、覆盖与追加；
- IndexedDB 自动保存；
- PNG、PDF 导出；
- 首次由用户点击“开始计算”，之后编辑自动重算；
- 现有课程和规则数据结构。

## 3. 总体信息架构

### 3.1 单窗口工作台

页面使用全高应用外壳，不再保留顶部宣传式横栏和纵向堆叠的大区块。

桌面端分为两栏：

- 左侧功能栏约占可用宽度的 28%–32%，同时设置合理最大宽度，避免超宽显示器上浪费空间；
- 右侧课程工作区占剩余空间，并始终不少于整体的三分之二。

### 3.2 左侧功能栏

左侧从上到下依次包含：

1. 产品标识 `JLU GPA`；
2. 功能入口：`课程`、`导入成绩`、`计算规则`、`结果导出`；
3. `开始计算` 按钮；
4. 三项结果摘要，顺序固定为：
   - 保研 GPA；
   - 加权平均分；
   - 算术平均分；
5. `关于` 入口。

主界面不显示规则、隐私或非官方警告横幅，也不在左侧底部显示“规则未核验 · 数据仅存本机”等状态句。必要说明只保留在“关于”窗口和导出结果页脚中。

只有发生导入失败、保存失败或导出失败等实际问题时，才显示临时错误消息。

### 3.3 右侧课程工作区

右侧顶部包含：

- 页面标题和当前视图名称；
- 搜索课程名或课程号；
- 筛选与排序；
- `添加课程` 主按钮。

课程清单固定使用表格，每门课程占一行。基础列顺序为：

1. 课程名，下方以次级文字显示课程号；
2. 成绩；
3. 学分；
4. 绩点；
5. 保研课程；
6. 操作菜单。

“保研课程”列只显示 `是` 或 `否`，不能显示“自动”。底层仍可根据当前规则得出初始状态；用户在界面中修改后，保存为明确的纳入或排除覆盖。

## 4. 导航和功能行为

应用采用单工作台模式，右侧课程清单不会因为点击其他功能而被替换。

- 点击 `课程`：关闭当前功能抽屉并返回全部课程视图；
- 点击 `导入成绩`：从右侧打开导入抽屉，保留文件选择、工作表选择、问题行、覆盖与追加预览；
- 点击 `计算规则`：从右侧打开规则抽屉，保留五级制折算表、分数—绩点表、绩点来源模式和保研排除规则；
- 点击 `结果导出`：从右侧打开导出抽屉，展示结果摘要预览与 PNG/PDF 按钮；
- 点击 `关于`：打开轻量窗口，显示本地数据、非官方声明、规则版本和项目信息。

关闭抽屉后恢复原来的课程滚动位置、搜索条件、筛选条件和选中结果视图。

## 5. 结果视图

三项结果在左侧以紧凑摘要显示，不使用大面积结果卡片。

- 未首次计算时显示“尚未计算”；
- 成功时左侧计算结果显示两位小数，其他位置显示一位小数；
- 无符合条件课程时显示“无可计算课程”；
- 点击保研 GPA、加权平均分或算术平均分摘要时，右侧表格切换到对应结果视图；
- 结果视图显示实际采用的课程，并允许显示被排除课程及具体原因；
- 点击左侧 `课程` 恢复全部课程视图。

## 6. 课程行与编辑抽屉

### 6.1 课程行

课程行高度约为 56 px，强调横向可读性。鼠标悬停仅使用浅灰背景，不使用抬升、发光或夸张动画。

“保研课程”允许在行内直接切换 `是/否`。切换后先写入 IndexedDB，成功后更新界面；保存失败时恢复原状态并提示错误。

每行末尾使用省略号操作菜单，菜单仅包含：

- 编辑；
- 删除。

### 6.2 课程编辑抽屉

点击课程行或“编辑”后，从右侧打开宽约 620 px 的抽屉；窄屏下自适应为视口宽度。抽屉包含：

- 课程号；
- 课程名；
- 学年学期；
- 成绩类型和成绩；
- 学分；
- 教务导入绩点及当前采用绩点来源；
- 保研课程 `是/否`；
- 是否参与均分；
- 课程类别（通识教育、学科基础、专业教育、跨学科拓展）和课程性质（必修、选修）选项；
- 成绩记录是否有效。

保存成功后抽屉关闭，课程行和三项结果自动更新。保存失败时抽屉保持打开并保留输入。

## 7. 视觉规范

### 7.1 色彩

- 页面背景：`#F5F6F7`；
- 内容面板：`#FFFFFF`；
- 主文字：`#1D232B`；
- 次级文字：`#707986`；
- 分隔线和边框：`#DFE3E8`；
- 强边框：`#C6CDD6`；
- 主强调色：吉林大学酒红 `#8F2C3E`。

酒红色只用于主按钮、选中导航、焦点和必要的关键状态，不铺满大面积背景。

### 7.2 字体与数字

中文优先使用 `Microsoft YaHei`，界面辅助文本可回退到 `Segoe UI` 和系统无衬线字体。结果和课程数值启用等宽数字特性，保证列对齐。

### 7.3 形状与层级

- 常规圆角为 4–6 px；
- 主要使用边框和背景色建立层级；
- 只允许抽屉、菜单和临时浮层使用轻微阴影；
- 不使用渐变、玻璃、霓虹、发光边框或装饰性插画；
- 不使用宣传式副标题、表情符号或无功能意义的装饰图形；
- 动画控制在 120–180 ms，用于抽屉、菜单和悬停状态。

## 8. 响应式设计

桌面端是主要使用场景。

- 视口大于 900 px：显示完整左侧功能栏和右侧课程表；
- 视口不大于 900 px：左栏折叠为约 64 px 的图标栏；
- 折叠状态下结果通过图标或紧凑数值入口访问；
- 课程仍使用表格，不改为卡片；
- 宽度不足时课程表在自己的容器内横向滚动，页面本身不横向溢出；
- 课程、导入、规则和导出抽屉在窄屏下占满屏幕宽度；
- 键盘焦点、工具提示和图标的可访问名称必须保留。

## 9. 组件边界

现有 `App.tsx` 职责过多，本次重构按以下边界拆分：

- `AppShell`：两栏结构、响应式折叠和全局抽屉容器；
- `Sidebar`：品牌、功能导航、开始计算和关于入口；
- `ResultSummary`：三项结果、选中结果视图；
- `CourseWorkspace`：标题、搜索、筛选、排序和课程数据编排；
- `CourseLedger`：逐行课程表、横向滚动和行操作；
- `CourseDrawer`：课程新增与编辑；
- `ImportDrawer`：文件导入及预览；
- `RulesDrawer`：计算规则编辑；
- `ExportDrawer`：导出预览及 PNG/PDF 操作；
- `AboutDialog`：非官方声明、隐私和规则版本。

组件只通过现有应用状态接口读取和修改课程、规则及结果。领域计算层、SheetJS 导入器、Dexie 数据库和导出器不依赖新的 UI 组件。

## 10. 错误与状态处理

- 初次加载 IndexedDB 时，在课程表区域显示骨架，不替换整个页面；
- 空数据时保留完整应用外壳，在表格区域显示简洁空状态；
- 导入解析在抽屉内显示进度和问题行；
- 保存操作禁用重复提交；
- 成功操作使用短暂消息；
- 失败操作显示明确原因，不使用常驻横幅；
- 删除课程必须二次确认；
- 抽屉关闭前若存在未保存修改，提示确认放弃。
